# README — AX 빌더 위키 사용 안내

이 문서는 GitHub 저장소를 사용하는 프로젝트의 공통 위키 관리 안내입니다. 사용자와 AI가 함께 읽으며, 프로젝트별 소개·설계·개발 이슈는 확인된 자료를 바탕으로 별도 Markdown 문서에 작성합니다.

## 저장 위치

- **위키 기능이 꺼져 있거나 `.wiki.git`에 아직 접근할 수 없는 저장소:** 코드 저장소 기본 브랜치의 `docs/wiki/`가 원본입니다. 공개·비공개 모두 같은 기준을 사용합니다. README는 `docs/wiki/README.md`에 자동 준비하며 기존 파일은 덮어쓰지 않습니다.
- **위키 기능이 켜져 있고 최초 페이지가 생성되어 `.wiki.git`에 접근할 수 있는 저장소:** 별도 위키 저장소를 사용합니다. 비공개라도 GitHub 요금제와 권한이 허용하면 동일하게 사용할 수 있습니다.

빌더는 실제 기본 브랜치와 위키 접근 가능 여부를 확인합니다. 코드 저장소를 공개하면 `docs/wiki/` 문서도 공개되므로 먼저 내용을 검토하세요. 자동으로 공개 범위나 위키 설정을 변경하지 않습니다.

## 처음 준비하기와 별도 위키로 전환하기

코드 경로의 README 생성에는 Contents 쓰기 권한이 필요합니다. 기본 브랜치 보호 규칙이 생성을 제한하면 `docs/wiki/README.md`를 작업 브랜치에서 추가하고 PR로 병합하세요. 보호 규칙을 우회하지 않습니다.

나중에 분리하려면 GitHub에서 Wiki 기능을 켜고 첫 페이지를 저장합니다. GitHub는 최초 페이지 생성용 공식 REST API를 제공하지 않습니다. 빌더 연결 자격 증명으로 해당 위키 Git에 접근하고 푸시할 수 있어야 합니다.

다음 동기화에서 빌더는 기본 브랜치의 `docs/wiki/` Markdown 문서를 위키 루트로 복사합니다. 하위 폴더와 상대 링크는 유지합니다. 대상에만 있는 문서는 보존하며, 같은 경로에 동일한 내용이 있으면 건너뜁니다. 같은 경로에 다른 내용이 있거나 문서 제목이 중복되면 전환을 중단합니다. 먼저 두 저장소의 충돌을 해결하세요. 강제 덮어쓰기는 하지 않습니다.

모든 문서 검증과 일반 Git 푸시가 성공한 뒤 별도 위키로 전환합니다. `.ax-builder-wiki-migration.json`에 복사한 원본 커밋을 기록하므로 이 파일을 삭제하지 마세요. 이후 코드 경로의 문서를 반복 복사하거나 삭제된 위키 문서를 되살리지 않습니다. 코드의 기존 문서는 자동 삭제하지 않으며, 전환 이후에는 별도 위키에서 수정하세요. 전환 중에는 코드 위키 수정을 잠시 멈추고 기록된 커밋 이후 변경이 없는지 확인하세요.

전환 후 위키가 비활성화되거나 접근에 실패하면 마지막 정상 게시본을 유지합니다. 코드의 오래된 사본으로 자동 복귀하지 않습니다. 이미지·첨부 파일은 자동 이전 대상이 아닙니다.

## 코드 저장소에서 수정하기

```sh
cd code
git status
git pull --ff-only
# docs/wiki/ 아래에서 필요한 문서를 수정합니다.
git diff -- docs/wiki
git add docs/wiki/수정한-문서.md
git commit -m "위키 문서 수정"
git push
```

브랜치 보호가 있다면 작업 브랜치에서 PR을 만들고 기본 브랜치에 병합합니다. 빌더는 작업 브랜치가 아닌 **기본 브랜치에 반영된 문서**를 게시합니다. 코드 저장소의 다른 Markdown이나 `docs/system/`은 프로젝트 위키로 읽지 않습니다.

## 별도 위키 저장소에서 수정하기

```sh
git clone <위키-저장소-주소> wiki
cd wiki
git pull --ff-only
# 필요한 문서를 수정합니다.
git add <수정한-문서-경로>
git commit -m "위키 문서 수정"
git push
```

이미 클론한 폴더에서는 클론·git init을 반복하지 않습니다. 코드와 위키의 커밋·푸시는 각각 확인합니다. 비밀번호나 토큰을 문서와 원격 URL에 넣지 마세요.

## 문서 형식과 탐색

```markdown
---
type: guide
---
# 고유한 문서 제목

문서의 목적과 적용 범위, 확인된 사실과 절차를 작성합니다.
```

`type`은 `overview`, `architecture`, `guide`, `plan`, `reference`, `release` 중 하나입니다. 목록에 종류 뱃지로 표시됩니다. 라벨은 작성하지 않습니다. 제목·경로·본문으로 검색합니다. 필요한 하위 폴더를 만들 수 있고 실제 폴더 구조가 트리에 표시됩니다. 위키 루트 README는 기본 진입 문서입니다.

문서는 상대 경로로 연결합니다. 예: `[사용 안내](../README.md)`. 파일 이동 시 링크도 수정합니다. 같은 제목의 문서를 중복 생성하지 않습니다. 파일당 512 KiB, 전체 5 MiB, Markdown 500개까지 지원하며 숨김 경로와 심볼릭 링크는 문서로 사용하지 않습니다.

## 반영 확인과 AI 작업 원칙

서버는 약 30초마다 원본을 확인하고 열린 화면은 약 15초마다 갱신합니다. 네트워크와 처리 시간에 따라 지연될 수 있습니다. 저장소의 추가·수정·삭제가 게시본에 반영되고 검색 색인은 별도로 갱신됩니다. 실패하면 재시도하며 마지막 정상 게시본을 유지합니다. 저장소 관리 문서는 화면에서 직접 저장하지 않습니다.

AI도 작업 전 README, 관련 문서와 실제 코드를 읽습니다. 기존 문서를 우선 수정하고 확인된 사실·제안·미완료 작업을 구분합니다. 변경 이유와 검증 결과, 관련 코드 커밋을 기록합니다. 비밀값과 개인정보를 복사하지 않습니다. 충돌 시 강제 푸시로 이력을 덮어쓰지 않습니다. 로컬 수정, 커밋, 푸시, 화면 반영, 검색 색인 완료는 실제 확인한 단계만 보고합니다.
