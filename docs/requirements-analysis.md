# GitHub 소개 페이지 요구사항 분석

분석 이슈: AX Builder #1382 · 프로젝트 36
작성일: 2026-09-07 · 상태: 분석 제안, 검토 전

## 1. 근거와 현재 상태

AX Builder `wiki.get`으로 조회한 핵심 Wiki 「프로젝트 요구사항」을 근거로 한다.
문서 ID는 6957, revision은 1, sourcePath는 `project-requirements.md`이다.
Wiki의 최초 요구사항은 다음과 같다.

> 간단한 github 소개 페이지 구축

Wiki 작업 원칙은 기획 단계에서 설계 이슈를 먼저 만들고, 그 설계 이슈를 근거로 개발 이슈를 생성하는 것이다.
검증과 배포는 이 Wiki와 실제 구현 결과를 기준으로 진행한다.

분석 시작 시 로컬 저장소는 `nextory-dev/temp`, 기본 브랜치는 `master`,
기준 커밋은 `96dd06e`이며 추적 파일은 `README.md`뿐이었다.
애플리케이션, 패키지 설정, 빌드 및 테스트 명령은 아직 없다.
이 문서는 요구사항 분석 산출물이며 소개 페이지의 구현이나 설계 승인을 의미하지 않는다.

GitHub 서비스 소개와 개인 프로필·조직·특정 저장소 소개는 서로 다른 결과물이다.
Wiki는 이를 구별하지 않으므로 P-01을 확정 사실로 취급하지 않는다.
설계 #1390에서 소개 대상을 확인한 뒤 최종 문구와 레이아웃을 확정한다.
이 확인은 분석과 작업 분해를 막지 않지만, 개발 착수의 선행 조건이다.

숫자·가격·기능 제공 범위 등 변경될 수 있는 제품 설명은 추측하지 않는다.
최종 문구와 링크는 설계 단계에서 공식 문서로 검증한다.
이 분석에서는 페이지 문구나 외부 링크 유효성을 검증했다고 주장하지 않는다.

## 4. 구성 선택지와 권고

1. **정적 HTML/CSS:** 단일 소개 페이지의 기본안이다. 설치·빌드 부담이 작고 별도 서버 API나 인증이 필요 없다.
2. **기존 프레임워크 기반 정적 페이지:** 향후 다중 페이지나 공통 컴포넌트가 실제로 필요할 때 고려한다. 현재 저장소에는 기존 프레임워크가 없다.
3. **GitHub API 연동 페이지:** 개인/저장소 통계가 요구될 때 별도 검토한다. 현재 Wiki에 근거가 없어 최소 범위에 포함하지 않는다.

권고는 1번이며 최종 선택은 #1390의 승인 설계를 따른다.
데이터 원천은 Git에 저장한 승인된 소개 문구이며, 자체 API·DB·사용자 계정 경계는 필요하지 않다는 가정이다.
실시간 데이터 요구가 생기면 이 경계를 다시 설계해야 한다.

개발 이슈 생성은 설계의 완료·승인 또는 개발 착수를 의미하지 않는다.
개발은 설계 리뷰가 승인되고 소개 대상·문구·레이아웃·링크가 확정된 뒤 시작한다.

기존 #1383 프로젝트 설계와 #1384 프로토타입 개발은 포괄적인 단계 이슈로 남겨 두었다.

담당자는 기존 단계 이슈에서 후속 이슈의 승인 결과를 근거로 단계 완료를 판단한다.
